Replit Update Request: Redesign Document Intake Workflow

Problem

Currently, when a user uploads a document:

1. The system immediately begins generating case summaries.
2. It creates factual gaps.
3. It generates investigative questions.
4. It creates a partial case file.

This is happening too early.

The uploaded document should be stored first, then HyperLaw should gather context from the user before any AI analysis occurs.

The AI should only run after the user explicitly chooses to analyze the document and spends a credit.

⸻

New Workflow

Step 1: Upload Document

User uploads:

* PDF
* DOCX
* TXT
* Image

System stores the file.

No AI analysis yet.

No factual gaps.

No generated questions.

No case summary.

No case index generation.

Simply display:

“Document received successfully.”

⸻

Replace the current AI-generated screens with a clean onboarding flow.

⸻

Extremely Important: Case Memory

Current concern:

“Will Claude remember the case?”

Answer:

No.

Claude API does NOT remember anything between requests.

Every API call is stateless.

⸻

Required Architecture

Create a Case Memory Database.

Each case should have:

{
  "caseId": "...",
  "documents": [],
  "timeline": [],
  "parties": [],
  "evidence": [],
  "notes": [],
  "analysis": [],
  "generatedDrafts": []
}

Claude should never be the memory.

The HyperLaw database should be the memory.

Claude only:

* Reads memory
* Updates memory
* Generates output

Then memory is saved back to the case.
